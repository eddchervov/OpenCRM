# OpenCRM Admin — Avalonia

[English](README.md) | **Русский**

Раздел администрирования ИИ-помощника управляет доступностью, каналами, моделями, бюджетами, доступом организаций, аудитом, расходами и сверкой неизвестной стоимости. Права изменения настроек и просмотра расходов проверяются раздельно; конфликт версии настроек требует повторной проверки администратором. Подробности — в [документации помощника](../../../../docs/ai-assistant.ru.md).

Карточка организации поддерживает принудительную архивацию и восстановление любых неудалённых организаций с правом `Admin.Users.Manage`, причиной и явным подтверждением. Действует прежний срок очистки архива в 30 дней; после потери ответа новое действие заблокировано до сверки статуса. [Серверный контракт и ограничения](../../../../docs/admin-organizations.ru.md). Для этих действий нужно обновление серверного API, отдельно от desktop-публикации.

Самостоятельный desktop-клиент на .NET 10 и Avalonia для Windows и macOS: вход по email и паролю, профиль администратора только для чтения и дашборд. Чёрная тема с белым текстом используется независимо от темы операционной системы.

## Запуск

Из корня репозитория:

```powershell
dotnet run --project src/OpenCRM.Frontend/Admin/OpenCRM.Admin.App
```

Базовый адрес API читается из общего файла `configuration/brand.json`, который копируется рядом с приложением. Переменная `OPENCRM_ADMIN_API_URL` переопределяет это значение. HTTPS обязателен, кроме HTTP на loopback-адресе для локальной разработки:

```powershell
$env:OPENCRM_ADMIN_API_URL = 'https://localhost:7142/'
dotnet run --project src/OpenCRM.Frontend/Admin/OpenCRM.Admin.App
```

HTTP разрешён только для loopback-адресов. Проверка сертификатов HTTPS не отключается. Клиент использует HTTP/1.1. Настройки API, ключи подписи JWT и доступ к базе данных в desktop не передаются.

Клиент использует серверные API аутентификации и администрирования. Сервер отвечает за вход, роли, разрешения и доступ к данным.

## Вход и права

- `POST /api/v1/auth/login` выдаёт пару токенов после проверки email и пароля.
- `GET /api/v1/admin/current-user` проверяет право `Admin.Access` или актуальную роль `System` на сервере. После успешного ответа открывается дашборд, если он разрешён, иначе профиль.
- Сервер сверяет административные роли и разрешения с БД при каждом запросе; снятие роли или удаление пользователя блокирует доступ с прежним JWT.
- Клиент повторно загружает профиль и права каждую минуту и по кнопке «Обновить» в профиле. При 401/403 профиля сессия закрывается; 403 дашборда закрывает страницу и обновляет права.
- В Windows refresh-токен сохраняется с защитой DPAPI текущего пользователя в `%LOCALAPPDATA%/OpenCRM/Admin/Sessions`, отдельно для каждого адреса API. Пароль и access-токен не сохраняются. При запуске клиент обновляет токены и проверяет профиль и права на сервере. Перенос portable-приложения на другой компьютер или запуск другим пользователем Windows требует нового входа. На macOS сохранение сессии пока не поддерживается.
- Истекающий access token обновляется через `POST /api/v1/auth/refresh`. После ответа 401 один раз повторяется запрос чтения профиля или отчёта.
- Обычное закрытие окна сохраняет вход. «Выйти» удаляет сохранённую сессию и вызывает `POST /api/v1/auth/revoke`. Перед отзывом истёкший access token обновляется. При отсутствии сети отзыв на сервере не гарантируется; локальная сессия удаляется. Истечение refresh-токена или отказ сервера в авторизации удаляет сохранённый вход; временный сетевой сбой его сохраняет.
- В Windows для одного пользователя запускается только один экземпляр desktop-клиента, чтобы параллельные окна не использовали один ротируемый refresh-токен.

Меню показывает только разделы, разрешённые текущей учётной записи. Пункты с отметкой «позже» являются заглушками и не открывают рабочие экраны. Профиль не содержит форм изменения email, ролей или прав.

## Счётчики меню

Значки пользователей, обращений и истории email показывают новые записи с последнего успешного просмотра соответствующего раздела. При первом использовании учитываются записи с начала текущего локального дня; затем непросмотренные записи сохраняются через смену дня и перезапуск приложения. Отметки хранятся в `admin.NavigationReadStates` для аккаунта и раздела.

Значок платежей показывает общую очередь оплаченных платежей с незавершённой обработкой или без загруженного чека, за всё время. Обработка завершена при статусе `completed`; чек присутствует при сохранённом файле или URL. Пока хотя бы одно условие не выполнено, платёж остаётся в очереди. Неоплаченные, отменённые и полностью возвращённые платежи в неё не входят. Просмотр раздела не изменяет эту очередь и не сохраняет для неё отметку просмотра.

При загрузке пользователей, обращений или истории email клиент получает серверную временную границу через `GET /api/v1/admin/navigation/counts?unread=true`. Только после успешной загрузки актуального экрана он подтверждает её через `POST /api/v1/admin/navigation/sections/{section}/viewed`. Ошибка или отмена загрузки не сбрасывает значок; события после границы остаются новыми. Параллельные подтверждения могут только продвигать отметку вперёд. Счётчики обновляются раз в минуту, а после подтверждения — сразу. Очередь предложений каталога показывает все ожидающие модерации заявки независимо от просмотра.

Запрос `/navigation/counts` без `unread=true` сохраняет дневную статистику для прежних клиентов. Для непросмотренных событий необходимы обновлённый сервер и миграция `AddAdminNavigationReadStates`; сервер без поля `AsOfUtc` не получает подтверждений просмотра от нового клиента.

## Пользователи

Раздел открывается с `Admin.Users.View` или ролью `System`. Таблица занимает оставшуюся рабочую область, заголовки и пагинация закреплены; размер страницы по умолчанию 50, доступны 25/50/100. Поиск по email/телефону применяется кнопкой «Найти» или Enter, размер страницы и переключатель удалённых применяются сразу. «Сбросить» очищает поиск и возвращает первоначальную сортировку. Отдельного фильтра UTM нет.

Сортировка выполняется сервером при нажатии на заголовки пользователя, техники, ТО, организаций, последнего входа, регистрации и UTM-источника; повторное нажатие меняет направление. Стрелка в заголовке обозначает текущий порядок. Счётчики техники, ТО и организаций показаны отдельными колонками сразу после пользователя, затем идут последний вход и регистрация. UTM-источник — метка первого привлечения пользователя, не способ авторизации. Тариф принадлежит организации; у пользователя нет личного тарифа. Нажатие на число организаций открывает их вкладку в карточке, где у каждой свои роль, статус и тариф. Список не загружает overview для каждой строки.

Карточка открывается кнопкой в строке, двойным щелчком или Enter на выбранном пользователе. Возврат сохраняет страницу, выбор и поиск. Выделенная строка и строка под мышью используют тёмные фоны с контрастным текстом.

«Карточка» содержит обзор, организации, подписки, платежи, технику и ТО, обращения, историю активности и индивидуальные возможности. Шапка показывает пользователя, статус, даты входа и регистрации, счётчики входов и организаций. Вкладки оформлены контрастными кнопками, обзор расположен в две колонки на широком экране, остальные записи показаны списком; поля показаны компактными колонками или строками «название — значение».  Во вкладке организаций показано только текущее членство или владение, отдельные карточки истории приглашений отсутствуют. Статус выбирается локально: активные по умолчанию, архивированные или удалённые; выбор сохраняется при обновлении карточки. Внутри организации показана дата вступления; дата и автор приглашения добавляются только при совпадении принятого приглашения с организацией, email пользователя и датой вступления. Если подходящее приглашение отсутствует в ответе API, эти поля не подставляются из других записей. При включённом коммерческом модуле вкладка подписок показывает только подписки организаций с локальным выбором активных (по умолчанию), завершённых или всех; выбор сохраняется при обновлении. Старые личные тарифы и события их истории не отображаются. «Личная техника и ТО» исключает технику с `OrganizationId` и показывает обслуживания только известных личных машин. API ограничивает общую выборку 30 машинами и 20 обслуживаниями; при достижении лимита это отмечено в интерфейсе, записи с неизвестной принадлежностью не выдаются за личные. Хронология свёрнута. Поля можно выделять и копировать; время отображается в локальном часовом поясе. Финансовые вкладки, платежи, подписки и тарифы доступны только при включённом коммерческом модуле и с `Admin.Billing.View`. Ответ карточки запрашивается только при открытии и по кнопке обновления; списки не обновляются таймером. При выходе и отзыве доступа данные очищаются, при уходе запросы отменяются. Обновление карточки сохраняет выбранную вкладку.

Используются существующие `GET /api/v1/admin/users` и `/users/{userId}/overview`. Сервер ограничивает некоторые коллекции последними записями: при достижении ограничения вкладка показывает это явно. Раздел доступен только для чтения; редактировать пользователя или входить от его имени нельзя.

Ограничение API: `overview` требует `Admin.Users.View` и может включать финансовые поля независимо от `Admin.Billing.View`. Desktop скрывает коммерческие данные при отсутствии доступа, но интерфейс не заменяет серверную проверку разрешений.

## Дашборд

Для доступа к дашборду требуется `Admin.Dashboard.View` или роль `System`. Дашборд показывает данные CRM за выбранный период («Сегодня», «7 дней» или «Месяц»): платежи, новые регистрации и организации, активность обслуживания. Финансовые карточки, предупреждения и суммы платежей доступны только администраторам с `Admin.Billing.View` или ролью `System`. Публичные посещения сайта, отчёты поисковых систем и рекламные источники в дашборде OpenCRM не отображаются.

Страница обновляется автоматически с выбранным интервалом (5, 10, 30 или 60 секунд; по умолчанию 60 секунд) или вручную. Интервал хранится в `%LOCALAPPDATA%/OpenCRM/Admin/dashboard-refresh.txt`. Общая статистика CRM загружается отдельно по кнопке «Загрузить статистику». Журнал запросов пользователей настраивается отдельно через `UserActivity:Enabled` и в стандартной конфигурации выключен. Запросы останавливаются, когда дашборд неактивен или окно свёрнуто; переход и выход отменяют незавершённые запросы.

Desktop-клиент читает `GET /api/v1/admin/dashboard` и, если включён коммерческий биллинг, API сводки платежей. Если необходимого контракта API нет, он сообщает об устаревшем сервере и не подставляет данные за всё время вместо результата за выбранный период.

## Структура

- `OpenCRM.Admin.App`: XAML, ViewModel, оболочка, настройки и жизненный цикл окна.
- `OpenCRM.Admin.Api`: HTTP, сессия и небольшие клиентские DTO без зависимостей от Domain, EF и серверных сервисов.
- `OpenCRM.Admin.App.Tests`: проверки ViewModel и настоящих XAML-экранов через Avalonia Headless.
- `OpenCRM.Admin.Api.Tests`: проверки сессии, обновления токенов, отказов и HTTP-контрактов.

Новые проекты находятся в папке решения `Frontend/Admin`. Старый Chrome-лаунчер `OpenCRM.Admin.Launcher` сохраняется отдельно.

## Проверки

```powershell
dotnet test tests/OpenCRM.Admin.Api.Tests
dotnet test tests/OpenCRM.Admin.App.Tests
dotnet test tests/OpenCRM.Infrastructure.Tests -p:BuildScenarioClientsOnBuild=false --filter 'FullyQualifiedName~AdminAuthenticationApiTests|FullyQualifiedName~AdminAuthorizationHttpTests'
```

Последняя команда использует Docker, PostgreSQL и RabbitMQ через существующую фикстуру. Она проверяет реальные контроллеры входа и профиля, Identity, JWT, отказ обычному пользователю, административные политики, обновление и отзыв токенов.

Для сохранения снимков настоящих XAML-экранов на тестовых данных:

```powershell
$env:OPENCRM_ADMIN_SCREENSHOTS = "$PWD/output/admin-desktop"
dotnet test tests/OpenCRM.Admin.App.Tests
```

Эти снимки показывают тестовый профиль, а не вход в рабочий сервер.

## Платежи и подписки

Коммерческий модуль по умолчанию выключен. Раздел доступен только при `PlatformPolicy:Commercial:Enabled=true` и разрешении `Admin.Billing.View`; для работы CRM подписка не требуется. Вкладки платежей и подписок организаций используют серверные страницы по 25, 50 или 100 записей, поиск, статусы и сортировку по заголовкам. Платежи можно отобрать за сегодня, 7 или 30 дней либо за всё время. Ограничение сводки в 300 платежей не применяется к этим спискам. Для будущих подписок предусмотрен отдельный статус «Ещё не началась».

Кнопка «Открыть», двойной щелчок или Enter открывают подробности и историю изменений. Возврат сохраняет страницу; выход и отзыв прав очищают данные. Для списка нужны новые серверные эндпоинты `GET /api/v1/admin/billing/payments` и `GET /api/v1/admin/billing/subscriptions/organizations`. При старой версии сервера клиент показывает сообщение о необходимости обновления.

## Сборки для ОС

```powershell
dotnet publish src/OpenCRM.Frontend/Admin/OpenCRM.Admin.App -c Release -r win-x64 --self-contained true -o output/AdminApp/win-x64
dotnet publish src/OpenCRM.Frontend/Admin/OpenCRM.Admin.App -c Release -r osx-arm64 --self-contained true -o output/AdminApp/osx-arm64
```

Для Intel Mac используется `osx-x64`. Сборка под macOS не заменяет проверку на MacBook. Команды публикуют автономные приложения. Подпись, установщики и автоматическое обновление ими не создаются.
