# 支付服务的边界

[English](payments-service-design.md) | [Русский](payments-service-design.ru.md) | **简体中文**

> 本页为机器译稿。涉及部署、接口或数据变更时，请同时核对英文或俄文原文。

支付服务与支付提供者进行技术交流。 网络应用程序拥有组织权限和商业政策;支付服务不指定角色或独立授予CRM访问权限.

基座安装有 `PlatformPolicy:Commercial:Enabled=false`:核心客户关系管理工作不需要订阅购买. 安装所有者提供销售者的细节,可用产品,价格,收货规则,供应商密钥,并允许返回URL. 不包括工作销售者配置。

<a name="processing-invariants"></a>

## 处理变异物

- 一个命令包含一个稳定的操作ID. 重复同样的命令不会产生重复的充电.
- 变更的金额,货币,或购买的物品,不得以同一ID替换以前接受的操作条件.
- 外部通知经过核实,在收件箱中持续,并用重复保护处理。
- 货币状况的改变与给予商业权益是分开的。 国家通过一个可靠的发货箱与消费者联系。
- 未知的请求结果需要提供者对账。 自动重复可能完成的电荷是不可接受的。
- 退款是一种金钱事实。 申请由商业层面决定先前所授予的应享权利的后果。
- 运行历史,行政变更原因,提供方ID保留进行核对;用户回复和日志中不包括秘密.

<a name="integration-and-validation"></a>

## 整合和验证

服务包括供应商适配器;它们的存在不能使付款成为可能,或者意味着某一卖方愿意接受资金。  见 [服务读取器](../services/payments/README.zh-CN.md) 和 [应用程序集成](payments-service-integration.zh-CN.md) 合同和配置。

连接前,验证"一能",重复命令中更改术语,重复webhooks,未知结果,调节,退款,以及重复的状态交付. 本地自动检查不会取代对已配置的提供者的验收测试。 手动 [工作单付款跟踪](maintenance-services-payments.zh-CN.md) 仍是一个单独的机制,本身不通过支付服务收取费用。
