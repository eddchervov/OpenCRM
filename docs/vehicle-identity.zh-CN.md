# 车辆标识

[English](vehicle-identity.md) | [Русский](vehicle-identity.ru.md) | **简体中文**

> 本页为机器译稿。涉及部署、接口或数据变更时，请同时核对英文或俄文原文。

 在创建车辆或快速预约时,制作和模型是可选的。  只有输入的数据被存储:未知 `BrandId`, `ModelId`, `ManualBrandName`,以及 `ManualModelName` 保留 `null`. 车牌,VIN,车身号,发动机号,登记证书,或者用户自定义的名称必须仍然标明车辆. 快速预约需要车牌.

`Vehicle · A667PO142`  是界面和文档的标签。  它不是作为制片人、模型或名称储存的。  如果只知道部分的制作或模型,则该部分会被保存;一个缺失的值永远不会被发明出. 用户定义的真名单独存储 。

同一车辆后可以手动在编辑器中完成,也可以与目录中的模型相匹配. 其车辆身份、预约、照片和历史没有变化。  随后的快速任命通过在组织内正常的牌照重新使用现有车辆。  通过车辆卡编辑车辆细节.

只有当制作和模型都手工输入时,才会为共享目录创建一个建议. 空字段和接口标签不会成为建议 。

## 遗产占位符

使用 `scripts/maintenance/audit-vehicle-identities.sql` 供审查;其中仅包含 `SELECT` 语句,而只读连接是合适的。

清理准备于 `scripts/maintenance/clean-vehicle-identities.sql`.  这是业务操作 `psql` 脚本,不是计划迁移。 应用如下:

1. 部署固定并停止创建占位符的旧版本实例 。
2. 运行审计和对脚本进行干运行,不包含 `apply` 参数。
3. 应用脚本 `-v apply=true -v backup_file=<new-absolute-path.json>` 使用已配置的连接。  为每次尝试指定一个新的备份文件,并将其保存在 Git 之外:它包含原始的车辆数据.
4.  再次进行审计,检查受影响的车辆卡。

脚本只处理没有目录链接的车辆,其中手动型号与车牌完全一致,名称与先前的“制作型号牌照”公式相匹配。  它清除了生成的模型和名称. 只有在与车辆类型的前占位符相匹配时,方能清除;保留了真能。 用户定义的名称,模棱两可的匹配,以及编目车辆保持不变.

 在作修改前,剧本会将原作的行保存为JSON.  如果写入备份失败, 清理工作将中止 。 只有在清除装置以外的车辆没有使用时,它才会删除待处理的相关建议。  经批准的建议和共享目录不变. 维护与历史联系得以保存.

清理支持干运行,回滚备份失败,保存真实的制作和历史,并重复执行而无需再作修改.  要在应用脚本后恢复数据, 请使用保存的值 : `Id`  在检查用户自清理后没有更新卡片后。
