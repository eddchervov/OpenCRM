<a name="customers-and-channels"></a>

## 客户和渠道

 一个组织将自己的机器人连接起来. 持久性的bot标识符与它的名称和加密的代号分开存储. 连接,已核实的外部客户账户,对话,消息,附件,以及读取的收据被存储在单独的相关表格中.

谈话列表由客户分组. 不明发件人仍单独联系:匹配姓名或电话号码不会自动将其链接到客户记录上. 已禁用连接保留其历史供查看 。

顾客开始与机器人通信或听从邀请. CRM不只用电话号码创建私人对话. 连接处理使用外部账户身份和事件时间戳,所以过时的事件不能取消新的状态 。

断开原子式取消链接,关闭发送的对话,清除自动通知地址,并取消未发送的消息.  如果已启动发送, 操作返回 `409`  直到结果为人所知。 仅接收到的信息无法恢复已撤销的链接 。 恢复机器人只恢复已验证的连接 。

移动一个对话并手动解开链接也使用单一交易. 旧链接仍然被取消,先前的通知地址被清除,待发信件被取消. 人工链接无法自动通知新客户。 MAX送出地址与聊天ID分开存储.

<a name="permissions-and-templates"></a>

## 权限和模板

服务器检查 `messages.view`, `messages.send`, `messages.manage`,以及 `messages.templates.manage` 与用户成员、组织类型和工作空间访问相结合。  无 `clients.view`,客户记录数据被隐藏;维护字段需要 `maintenance.view`.  对每个雇员分别跟踪读取状态。

团体和模板属于通信单元。  它们支持命令、版本和存档;编辑过时的版本返回冲突。 允许替换: `organization.name`, `client.name`, `maintenance.date`, `maintenance.time`, `maintenance.vehicle`.  不执行任意表达式和脚本 。

预览使用已保存的模板版本,对话,以及可选的维护记录. 员工可以编辑并手动发送文本. 消息存储 最终文本, `MessageTemplateId`, `MessageTemplateVersion`,以及 `MaintenanceId`; 后期模板更改不会改变历史. 重复同样的请求 `RequestId` 返回已有信件。

 如果维护记录指明了买方,其上下文可在买方的谈话中找到。 车辆所有人仅用于没有买主的更古老的记录.

<a name="delivery-and-recovery"></a>

## 交付和回收

电文和送出意向书写在主数据库中的一个交易中. RabbitMQ接收提供者和消息/请求ID;消息文本,令牌,文件字节不放入队列. MAX和Telegram队列是分开的,有有边界的队列大小和同位素.

通知服务首先将命令写入一个耐用收件箱,然后确认为RabbitMQ. 受约束的处理人员从数据库中租赁工作;尚待尝试,而不是无限期地重新排队。 供应商、电文和 `RequestId`.

 对于多个应用程序, `Conversations:ApplicationId` 选择对话应用程序,并必须匹配相应的客户端 `RabbitMq:ApplicationId`. 只有在有一个应用程序时才允许自动选择。

尝试的起步在对外通话前记录. 回收使用上一个 `LeaseId`:从数据库中读取一个确认的结果,而外部通话开始后丢失的结果则被标记为未证实,不会自动被怨恨. 雇员在再次发送前核实收据。 完全的交货保证取决于信使的本能支持.

较早的待发或发送消息会在同一次谈话中阻断后续消息. 主动租借或延期尝试后,API返回 `409` 与 `Retry-After`;等候时间以24小时为限.

<a name="files-and-log"></a>

## 文件与日志

出行文件仅限于20 MB,在存储到S3之前使用数据保护进行加密. 内容访问通过一个授权的API,没有与解密文件的公共链接.  不完全上传被员工和谈话隔离,一天后被删除.

来信文件通过一个经核实的提供者连接被下载,并保护了API. 任意的URL不被接受; MAX URL在联系到CDN之前被验证, 并不会被传送到CDN. 即将到来的文件可用性取决于提供方是否保留了消息,连接是否仍然有效;文本和元数据被存储在系统中.

通知日志显示事件、最后文本、频道、时间和结果。 查看日志不会触发另一个发送 。
