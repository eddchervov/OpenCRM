<a name="preparing-and-downloading"></a>

## 准备和下载

`POST /api/v1/organizations/{organizationId}/data-export` 与反CSRF的保护队列 一个持续的工作。 重复请求会在24小时内返回相同的活动任务或即时存档. `GET .../data-export/status` 返回状态; `GET .../data-export/{jobId}/file`  {\fn黑体\fs22\bord1\shad0\3aHBE\4aH00\fscx67\fscy66\2cHFFFFFF\3cH808080}一个准备就绪的ZIP 遗产 `GET .../data-export` 仅下载一个已经准备好的归档;它不会启动构建。

组织模块拥有队列; WebApp 运行后台 Worker. 国家是: `queued` → `running` → `ready`; 失败导致 `failed`,并删除已准备好的文件结果。 `expired`.  一个独特的部分索引可以阻止一个组织的两个排队/运行工作。  一个简短的共享 PostgreSQL 交易锁限制了整个队列大小;一个单独的咨询槽允许使用该数据库在所有应用程序中构建一个。 槽被保存到存档上传到存储完成.

ZIP格式版本1和清晰的字段列表被保留. EF通过上下文相继读取行而无需重试缓冲,跟踪,或Auto Include. 元数据在可重复读取下收集;交易在相片和文档访问前结束.  文件列表和缺失的附件被存储在临时的JSONL文件中.  附件一次复制一个,而不对已经压缩的媒体进行再压缩. ZIP被写入了临时磁盘,而不是记忆结构. 存储接收该流而无需额外的SHA-256通路.

客户端对活动任务状态进行投票,并要求浏览器通过被保护的URL下载;它不会为整个文件创建 Blob. 准备和下载错误在设置中显示. 关闭区域会停止投票, 但不会删除服务器任务; 返回后会重新装入状态 。 只有在用户点击后区域仍然开放时,才会在准备后自动下载。

每日限制在成功完成后开始,而不是应要求开始. 遗产 `LastDataExportRequestedAt`  未使用,因为它可能包含前一个机制的失败尝试。 工作失败允许在短暂延迟后再次提出请求。  再次下载已准备好的归档不会重建 ZIP 。  如果缺少准备对象,则任务会失败并解除日限. 公布结果与CAS一起执行,并在一次交易中审计:如果承诺结果不明,一个已经准备好的档案不能被撤销.

队列任务在重新启动后幸存; 前一个 `running` 任务一旦解出槽口就被标记失败,而无需自动重试。 用户可以再次请求. 正常的失败不会隐藏历史或修改组织的业务数据.

<a name="resource-limits"></a>

## 资源限制

设置在 `OrganizationDataExport` (用于WebApp环境,前缀) `OPENCRM_OrganizationDataExport__`):

| 参数 | 默认 |
| --- | --- |
| MaxArchiveBytes | 1个GiB 完成 ZIP |
| MaxSourceBytes | JSON的4个GiB和附件实际上读作 |
| MaxRows | 总计100万行 |
| MaxFiles | 20 000个附件 |
| MaxTextCharacters | 文本字段中的2 000 000个字符 |
| MaxJsonFieldBytes | 8个维修史小米 |
| TimeoutSeconds | 准备和上传900秒 |
| MinimumFreeDiskBytes | 1个 GiB 免费; 建筑前检查, ZIP 每16个 MiB 输出 |
| QueueLimit | 20个已排队/正在运行的任务 |
| RetryDelaySeconds | 失败后60秒 |
| RetentionHours | 准备备案24小时;24–168允许 |
| SpoolDirectory | 单独 `opencrm-exports` 系统临时内目录 |

 两个共享的 PostgreSQL 槽限制同时下载. 流会释放一个弃置位置的槽,包括在中断了HTTP连接后. 限制使用实际字节计数; 未知的内容 - Length 不绕过它们 。  如果超过限制,则不交付部分ZIP:任务收到明显的失败并删除临时文件. 仅在检查磁盘和目标服务器运行时间后,才会增加设置 。

 这限制了一个操作的大小;它不能保证零负载. EF实现一行;在此之前,服务器验证拒绝过长的导出字符串和JSONB. PostgreSQL 在验证过程中仍然处理JSONB值本身. 数据库S3和网络上的满载必须按生产规模单独计量;当地32个米B测试确认流出副本,但不取代该计量.

闲置时,工人每15秒只执行一次轻量级数据库检查,而不创建S3客户端;在工作时会暂停3秒. 准备/失效的物体分批清理5个;30天以上的元数据没有文件的分批清理100个。 带有服务自身前缀的旧 spool 文件在超时间隔的两倍后被删除;不相干的文件和还原点不被删除. 保留审计数据。

<a name="private-storage-and-deployment"></a>

## 私人储存和部署

已完成的 ZIP 需要 a **单独** `S3:PrivateBucketName` (`OPENCRM_S3__PrivateBucketName`).  在任务排队之前, 拒绝一个空名或一个匹配正则桶的名 。 常规媒体继续使用已存在的"桶". 存档密钥和S3 URL从不返回客户端;下载会通过重新检查所有权的API.

 在启用安装导出前 :

1.  为 put/get/删除准备单独的私人桶和应用程序访问权限。  在保护配置中添加私钥设置, 并明确将变量传递到 OpenCRM 编译; 更改 `.env` 单靠自己是不够的。 拒绝匿名读取并上市于桶政策;单凭任意的GUID和私人ACL并不能保证这一点.
2. 测试一个实际的匿名GET以获取准确的测试密钥:必须拒绝访问,包括通过外部的CDN/域. 本地的S3模拟不能证明生产准入政策。
3. 配置生命周期规则以删除下方的对象 `organization-exports/`  在8天之后作为防范被删除组织和数据库元数据丢失的保障措施; 不影响商业媒体。  随后正常清理已准备好的文件 `RetentionHours`.
4. 分配一个拥有足够空闲空间的集合目录 。 增加归档限制需要重新计算磁盘储备.  不将数据库或S3数据放入此目录 。
5. 检查迁移 `20261030065903_AddOrganizationDataExportJobs` 对照所选的发布并应用到标准进程;然后检查所有者/成员的访问,排队/准备状态,重复下载,失败,并在失败后重试.

上面只创建一个组织FK和索引的工作表。 向下删除队列和已准备好的ZIP元数据而无需更改业务数据或审计;SQL回滚不删除S3文件.  在故意回滚之前,先把工人拦住,再将未完成/准备好的物件清单保存到私人桶中进行清理;在回滚应用程序时,不要自动回滚数据库. 之后的 Up 创建了空队列 。

 该套装还包括: `20261030073145_ExpandOrganizationAuditDescription`:审计 `Description`  从 varchar( 1200) 更改为文本, 因为一个完整的角色许可更改超过了先前的长度并取消了保存 。 上面保存着历史。 向下锁定表格,如果描述超过1200个字符,则以出错拒绝;没有发生自动截取.  在这种情况下,如果没有关于保留审计记录的单独决定,就故意无法全面收回计划。

正常的即时存档保存时间为24小时;安全寿命周期规则为8天. 照片留在现有的桶里。
