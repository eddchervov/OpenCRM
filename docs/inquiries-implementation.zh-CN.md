<a name="user-workflow"></a>

## 用户工作流程

“查询”部分可在“客户”下查阅。 董事会显示四个开放阶段;清单支持搜索、来源、受让人、阶段和下一个行动到期日。 封闭式和转换式的询问可通过过滤器提供。 服务器计算计数和数据页;初始移动视图为列表.

调查可以不设客户简介、车辆、电话号码、工位或预约时间:需要联系和说明客户的利益。 用户可以设定受让人,客户提供的车辆说明,以及下一个行动,在该组织的时区有一个到期日。 变化和笔记都记录在历史中. 完成一项行动可以澄清其目前的期限;结束调查需要理由。 工作日包括一个“接触客户”小组,其行动应在选定的日期和逾期的行动上进行。

“创造性任命”打开了选定情景的现有表格,并附有确认的链接、兴趣和车辆说明。 雇员确认服务、车辆、时间和工位。 明确选择一个已有的客户;创建一个新的客户需要一个单独的复选框,并在同一交易中发生. 匹配的电话号码不会自动选择一个人:表格会为现有的客户提供选择. 普通的客户创造流保持了现有的规则.

转换在两种操作模式中都形成计划任用. 重复请求返回上一个结果 。 调查走向“编造”与工作秩序和历史事件有联系,其下一项行动已清理完毕。 取消或移交工作命令不会重写询问历史.

 在一张服务卡中,“服务历史”打开了一种模式,包括事件、细节、作者和时间。 现有的创建活动是 " 从询问中创建的任用 " ,与来源有联系:维护通过客户模块读取存储的关系 `IOrganizationInquiryOriginReader`.  这支持旧的转换,而无需重复事件或迁移.  若为: `inquiries.view` 缺少, 特性被禁用, 或者无法使用情景, 源链接被隐藏, 而服务历史仍然可用 。 时间使用组织 `ShiftTimeZoneId`; 如果未设定, 则使用浏览器的本地区域 。

<a name="architecture-and-access"></a>

## 建筑和准入

- `OpenCRM.Modules.Clients/Inquiries` 拥有调查、历史、阶段和下一步行动。 公共 DTO 和接口在 `Clients.Contracts`.
- `OpenCRM.Modules.Organizations/Bookings/OrganizationInquiryBookingService`  通过客户合同和现有的快速预订服务协调转换。 控制器处理HTTP和用户上下文.
- `OrganizationInquiries` 和 `OrganizationInquiryEvents` 使用关系性外国密钥和索引;非空结果链接是独一无二的。 EF实体不通过跨模块合同被曝光.
- 调查锁锁、版本检查、客户/车辆/工作订单的创建、关系和历史都一并处理 `IApplicationUnitOfWork` 带有明确保存的交易。  每次尝试的输入副本保护交易重试, 避免被先前尝试修改的 DTO 。 现有的维修保障检查湾的可用性。
- `inquiries.view` 和 `inquiries.manage`  在许可目录中注册。 管理需要查看;转换还需要允许才能创建服务.  在服务器上检查订阅和只读模式 。 Fleet没有新的区域或工作流程 API.
- 无法访问的关系被隐藏在响应中,在其他字段被编辑时保留. 现有关于软删除简介的参考文献仍然存在;对新的参考文献进行了检查,以了解组织所有权和车辆/客户的一致性。  一个版本冲突返回了 HTTP 409.

<a name="interface-improvements"></a>

## 接口改进

简介将询问和客户联系、工作行动以及一个分组的外地编辑分开。  可选客户和车辆链接分别扩大. 剖面图的下方显示最近发生的三起事件和注释,并有内置选项来添加注释. 完整历史以模式打开 `dialog`,打开时加载,并有它自己的出错和发号施令。 共享 `InquiryTimeline` 和 `InquiryNoteComposer`  在两地提供一致的渲染和注释条目。 逃出关闭对话框并恢复焦点;打开注释编辑器将焦点移动到文本字段.  一个版本的冲突保留了说明草案. 完成一个动作可以显示历史中已完成的任务文本而不是一个空值;关闭可以显示没有遗留的舞台代码的原因. 被更正的显示也适用于以前被保存的事件.

 在改变开放舞台时,用户可以提供最多可达1000个字符的可选评论. 已经保存下来了 `Description` 同样的, `stage_changed` ,在更改舞台并检查版本的交易中。 旧的和新的相位代码仍然是单独的值;时间表既显示过渡,也显示评论. 旧的合同方法被保留为超载; HTTP 请求添加了无效 `comment` 字段。 允许空评. 未知或已关闭的阶段, 再次选择当前阶段, 和评论太长, 会被拒绝而不记录一个事件 。 关闭仍然需要它自己的行动和理智。 不需要移徙,因为: `Description` 栏已存在。 HTTP 409后刷新数据保留了主编辑稿和阶段更改注释;保存一个普通的注释也使所选阶段不变.

董事会重新设计了舞台头,柜台,卡片,和空状态. 过滤器从显示活动条件计数和重置选项的按钮中扩展;视图共享一个切换器. 列表有栏标题和显示阶段、受让人和到期日的移动布局。

编辑器中的车辆搜索 `InquiryVehiclePicker`,通过细化和汽车服务共享.  结果直接出现在搜索字段下方,从一行中选择,所选择的关系通过明确的动作单独显示并去除. 输入开始搜索而不保存询问 。  第一个结果得到焦点,并被带入视野;空结果,出错,加载被明确显示. 更改查询或客户端会使 stale 响应无效; 新的搜索无法清除已经选中的载体 。  结果限于每页有5行,带有服务器侧平面图.

 应交日期使用共享 `UiDatePicker` 和 `UiTimePicker`. 选取时间的人可以选择 `align` 设置弹出对齐; 狭义的询问字段使用右对齐。 `Organization.ShiftTimeZoneId` 在配置时,定义了该组织的当地时间。  如果没有配置, API 返回 `timeZoneId: null`; 界面清晰显示用户的本地区域, 并发送浏览器的 IANA 区域在机上, 列表和工作日请求 。 服务器只在组织没有配置区域时才将其用于日边界;未知区域被拒绝. Instants被存储在协调世界时,并在选定的局部区域显示并编辑.  一个不变的到期日保留了最初的一分时间,包括时钟在秋天返回时的模棱两可的时间.

 没有针对一个大型客户目录进行负载测试;明确的客户创建可重复使用现有的潜在重复搜索。

<a name="migration-and-local-environment"></a>

## 移徙和地方环境

移徙 `20261023100103_AddOrganizationInquiries` 由EF Core 10.0.7创建. 密码 `DbContext` 和 `Migration` 设计器中的属性,类/标识匹配,两个配置文件,快照都被检查; `has-pending-model-changes` 报告没有差异。

`Down`  删除空表格。  如果存在查询,则在删除前故意停止回滚:必须以协调的方式保存并恢复数据。 没有任何自动回滚会破坏历史。

标准本地 HTTPS 配置文件 `https://localhost:7142`; 设置步骤在 [README](local-run.zh-CN.md). 通知发送默认被禁用 。 安装所有者分别配置外部集成.
