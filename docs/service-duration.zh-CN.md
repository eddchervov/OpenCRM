# 服务工时

[English](service-duration.md) | [Русский](service-duration.ru.md) | **简体中文**

> 本页为机器译稿。涉及部署、接口或数据变更时，请同时核对英文或俄文原文。

服务和成套服务目录现在有一个可选的“期限、分”字段。  它规定了一个工位被占用的连续时间,包括干燥和等待. 值为从1到52.5600的整数;空字段指持续时间不明. 列表和选择菜单以小时和分钟显示时间. 详细设置向导中也提供服务时间.

 在创建预约时,在开始和选择服务后计算计划结束日期和时间. 期限根据服务量进行总和。  从菜单中选择的完整服务集可以有自己的持续时间;如果没有设定,则使用其组件服务的持续时间.  如果整套服务不是任用的一部分,则使用其余的个别服务。 重叠组合中的共享服务只计算一次。 额外的服务单位分别延长服务期限.

 如果任何所需服务的期限不明,则无法准确计算。 先前自动计算的结束时间被清除;手动输入的结束时间被保留.  当用户更改结束日期或时间时,自动重新计算被禁用. “计算结束时间”按钮明确恢复服务计算。

对现有预约的自动重新计算是禁用:打开编辑器,更改目录,或更改服务列表本身不会移动调度.  一个服务集和以前一样被扩展为单个服务;当以当前形式选择一个服务集时,它被覆盖的时间被使用. 节省了具体的计划任用日期和时间。 编辑器中明确的重新计算使用现有的服务构成,因为被存储的行不保留其历史设定的会籍.

夜间和非工作时间是持续时间:这是工位占用,而不是技术员的劳动时间。 占用情况由现有的间隔验证检查,包括整个午夜。  如果一项任命有冲突,则无法挽救。 公共网页不变;计算采用共享组织表格和快速详细及服务站预约。

## 核查

服务器测试可验证保存、更新和清除持续时间、无效值、服务集、保存现有预约时间表,并通过向导进行保存。 使用测试 API 对已建客户端的浏览器检查涵盖持续时间和数量,午夜,人工结束时间,未知持续时间,成套服务,工位冲突,提交日期和时间,现有预约,以及宽度为320–1440 px的轻/暗主题.
