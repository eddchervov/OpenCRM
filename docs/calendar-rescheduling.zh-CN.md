# 调整预约

[English](calendar-rescheduling.md) | [Русский](calendar-rescheduling.ru.md) | **简体中文**

> 本页为机器译稿。涉及部署、接口或数据变更时，请同时核对英文或俄文原文。

详细 " 预约 " 一节:

- 在日历中,一个有起止的预约可以被拖到另一个时间或一天. 其持续时间得到保留,包括整个午夜和多天。
- 在“槽”模式下,最初的预约卡可被拖到另一个时间和工位牢房。
- “重新安排”按钮不拖动地打开同样的窗体;该按钮可在日历和初始档卡中找到。  通过日历按钮重新安排未及时的预约,并明确选定时间。
- 拖曳打开确认对话框 。 预约在节省之前保持原有位置。 窗体显示旧间隔并允许新的日期、时间和工位。 更改起始日期将结束日期改为相同的天数。
- 已完成和被取消的预约不能重新安排。 动作被隐藏在只读模式中,并且没有编辑权限.

现有 `reschedule` 动作在 `POST /api/v1/maintenance/{id}/workflow` ; 没有创建新的保存路由。 服务器重新检查权限, 状态, 以及交易内的全部计划间隔 。  在改变工位时,它会检查当前组织的活性目录;一个不变的后继名称仍然相容. 空字符串会去掉工位任务;省略的字段会保留其值不变.

日历响应包含一个数字状态, `version`,以及 `canReschedule`. 表格发送了显示的预约版本:在锁定行后,服务器拒绝一个 stale 版本. 版本字段对于现有的客户端仍然是可选的.  同时期湾入住由现有的交易湾锁和重叠检查保护.

历史记载了新旧的日期,时间,和工位. 服务、付款、实际日期和状况在重新安排期间不变。 调度在保存后被重新装入 。  通过拖放调整事件大小不包含;结尾可以在表单中被明确更改.

新的界面仅在"详细日历"中启用. 共享服务器合同的延长是相容的。 公共网页以及服务站和舰队时间表没有改变。 重新安排时间本身就不需要移徙。

核查包括建造WebApp和所有三个客户端;服务器测试,以便迁移到另一个工位、多天间隔、保存服务和历史、陈旧版本、占用/外国/不活跃工位以及封闭预约。 浏览器检查覆盖了在槽,周,月视图中的实际拖放;取消,验证/服务器出错,权限,只读模式,轻/暗主题,宽度为320–1500 px.
