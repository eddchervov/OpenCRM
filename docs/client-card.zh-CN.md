<a name="comment"></a>

## 注释

客户简介及其形式使用一个“评论”字段,以4 000个字符为限。  如果超过限制,服务器会用字段级消息返回HTTP 400;拒绝的更改不会被保存. 遗留的 API 参数 `Notes` 已接受兼容性,并合并为 `Comment`. 搜索和导出使用统一注释.

 当上一个 `Comment` 和 `Notes` 字段迁移,如果两者不同,则用分隔符保存。  同值不重复。 将一个被合并的值分回原字段是模棱两可的,所以如果已经写入了被合并的数据,则必须停止一个计划回滚.

评论意见可通过下列方式单独编辑: `PUT /api/v1/organizations/{organizationId}/clients/{clientId}/comment`. 行动检查 `ClientsEdit` 权限,并仅更改注释和更新时间戳。 错误保存已输入的草稿; 取消不会改变数据 。

<a name="service-history"></a>

## 服务历史

历史逐页被载入 `GET /api/v1/organizations/{organizationId}/clients/{clientId}/maintenances`. 参数为: `page`, `pageSize`, `searchQuery`,以及 `status` (`upcoming`, `completed`,或者没有过滤器)。 页面尺寸限制为 1–100 。  在计算和选择记录之前应用了搜索和过滤;按日期、创建时间和标识符顺序稳定。

历史与客户有关 通过 `BuyerClientId`,包括当车辆更换车主。 已删除的工作订单和车辆不包括在内;档案车辆仍然可见。 查看需要允许读取工作订单,只有在用户有财务访问权限时才返回财务价值.  为当前页加载付款;概况总数由数据库汇总计算出。

<a name="identity-information"></a>

## 身份资料

个人的姓氏、姓名和父名分别保存。  每部分限定为60个字符,全名为160个.  在创建或更新个人细节时,需要有一个特定的名字;姓氏和父系是可选的。  一个组织或独资商有一个最多有160个字符的名称领域.

 这些字段在客户名单答复和组织出口中都是无效的和可用的。 现有 `Name` 值不自动解析; 遗留的 API 有单个 `Name` 字段仍然支持。

<a name="tax-details"></a>

## 税务详情

组织类型决定了税收细节格式. 税务识别号码(INN)包含一个法律实体的10个数字,或一个独资商的12个数字。 注册理由代码(KPP)仅供法律实体使用,包含9个字符;拉丁字母在5–6号位置允许使用. 值可能用空格粘贴;引导的零被保留. 格式验证不验证纳税人登记.

 对于没有已知组织类型的遗留的API请求和记录,先前的税收细节字段仍然支持20个特征限制.  在选择组织类型后,严格验证适用.
