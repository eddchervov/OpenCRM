<a name="changes"></a>

## 变动

 在详细和汽车服务服务器菜单中,现有网页分为以下几组:“每日工作”、“客户”、“资源”、“报告”和“帮助和访问”。 日常工作从工作日和任命开始,然后酌情发布汽车服务工作订单,然后是服务期刊和可视化。 “我的工作”仍按现行规则提供。 页面代码,业务段名称,URL,以及权限检查被保存. 现有舰队组织的菜单没有重新组合。

现有的共享导航组件被使用:在桌面上显示在左边,在手机上显示在模式抽屉.  没有添加全局标签或新的业务部分。

 在返回详细或自动服务预约时,恢复选定日期、列表范围、视图、选定工位、可用时间段以及工位视图中的指定搜索。 日历导航保留当前查看的日期. 工位过滤器在“湾”和“槽”之间共用;长度适用于槽。

上下文存储于 `sessionStorage` 用于当前用户和组织。 观点偏好 `localStorage` 范围也扩大到用户;一个组织共享的遗留密钥不再适用于新用户。  如果浏览器阻挡了存储,屏幕会起作用,但不会在导航后保存状态. 无效的值被验证,而且过长的时间不能产生无效的结束日期 。  在目录加载后从过滤器中去除被删除的工位;如果目录请求失败,则过滤器被清除,从而无法隐藏调度.

客户、车辆和服务日记清单已经具有自己的过滤持久性;这些机制没有被改写。  全浏览器历史和面包屑 URL 没有更改 。 没有任何新的普遍“恢复原任命”行动来自每个档案:档案回归链接使用现有的链接和历史,而打开“任命”则恢复时间表视图。

## 核查

- 前端: 完整 `node --test tests/*.test.mjs` 运行包括上下文恢复、组织/用户隔离、不可用和无效的存储、过多的日期范围以及目录负载故障。
- 服务器: 完整 `OpenCRM.Modules.Workspace.Tests` 运行包括 shell 检查和一个权限矩阵,用于细节,汽车服务,以及保存的情景.
- 细节,汽车服务,以及车队CRM客户端建设成功. 依赖性审计和分析器设置没有改变;依赖性审计、汇编和客户捆绑大小警告仍然存在。
- 浏览器在宽广的取景口宽度下对照演示API进行检查,发现三个CRM客户端中没有全页水平外溢. 审查了光明和黑暗的主题。
- 在详细介绍中,界面用于打开客户端并返回所保存的日期,“槽”视图,所选择的工位,持续时间,并在工位视图和日历中恢复搜索.
- 在具有受限权限的移动汽车服务中,检查了可用组和没有财务项目的情况;无法以只读模式创建预约。 逃出会关闭菜单并返回焦点到其触发器.

 没有数据库变化或迁移。

## 本地预览

```powershell
node tests/serve-visualization-preview.mjs
```

细节 : `http://127.0.0.1:5178/tests/scheduler-preview.html?navigation&empty&posts=3#scheduler`.

 对于汽车服务,请添加 `scenario=autoservice`; 使用时 `readonly` 用于只读模式和 `restricted` 用于有限的演示菜单。 密码 `navigation` 参数只允许在测试带中使用新菜单;生产客户端在没有此参数的情况下从服务器 DTO 接收分组导航.

 该接头使用真实的Vue组件并测试API响应.  它核查接口;它不会对工作数据库运行完整的应用程序。 日历带中的一些相邻页面没有测试的API响应:开通客户验证屏幕导航和回放,但并不是对客户和车辆配置的全面业务测试.  没有使用生产数据。
