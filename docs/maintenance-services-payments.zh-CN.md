# 工单服务和收款

共享组件由Stailing,Service Station,和Fleet使用. 公共网页不变。

<a name="working-in-the-interface"></a>

## 在接口中工作

- “选择服务”打开了对服务和成套服务的标签搜索。 多个项目可以选择并加在一起. 已添加的项目被标记,不能添加两次 。
- 服务行显示数量、单价和总额。 数量是一个正整数。 可根据需要扩大说明范围。
- 一个服务可以在目录中标出价格. 一组属于本组织的定期服务参考;在增加这些服务时,从这些服务中提取价格。 包含存档服务的集在它的组成被固定之前无法添加.
- 编辑卡片上的构成只保存服务. 材料及其记录费用、任用状况、日期和付款保持不变。
- “接受付款”列在未清余额旁边。  建议全额余额,可以接受部分支付. 超过当前余额的数额不予核准。
- 历史显示了数量,时间,雇员,以及评论. 会计错误可以按规定的理由倒置.  这不是银行退款。
- 付款变化要求 `finance.manage`; 需要更改服务 `maintenance.edit`.  只读模式块会改变 。

<a name="cancelled-appointments-and-financial-totals"></a>

## 取消的任用和财务共计

被取消的任命不产生应计或未完成的工作的债务。 已记录的付款不会自动删除。 用户可以单独注销一段经过历史记录的不正确的付款,但有需要的理由;这不是银行退款。  在重新任命时,应计和债务从节省的估计数和现付款中重新计算。

当地固定办法将财务预测的能见度分开(`IsVisible`列入应计项目(`IsAccruable`).  对于取消的订单, `NetAmount` 和 `DebtAmount`  是零; 原样 `GrossAmount`,折扣和订单行保留。 实际记录的材料和劳动力没有被去除;利润反映的是剩余的成本为负数. 活期付款仍列在汇总表中。 取消的工作被排除在订单清点、应计和大众服务之外,而财务清单中则有“取消”标签的记录。 报告按订购日期保留了先前的付款类别;这不是按收到资金日期分类的新的现金报告。

移徙 `20261030224000_AddMaintenanceAccrualFlag` 重新计算旧的财务行和一次交易中的小时汇总,并更新涵盖指数. `Down` 恢复先前从订单和行中得出的计算;源订单,付款及其历史不变. 切换时停止由旧应用程序写入 。  如果仅将应用程序回滚,则由旧的写作机不支持新旗;在返回到新版本之前,需要从源数据中协调地重新计算投影和小时摘要.  在应用程序启动时,既不进行自动数据库回滚,也不进行自动全数据库重新计算。

分别按照部署指令检查生产数据库.

<a name="shared-simplified-detailing-and-service-station-mode"></a>

## 共享简化细节和服务站模式

组织设置提供了一个共享的“简单/按阶段”选择器。  在简单模式下,未来的预约将被保存为 `Planned` 并保留时间;主“手接”按钮完成工作,并记录一次行动的实际移交。 中间阶段被隐藏在卡上. 指派一名雇员而不开始工作并不需要虚构的完成标记;现有的检查仍能保护真正的未完成的跟踪工作和未解决的额外工作。 付款仍然是一项单独的业务。

 以前完成的任用保留了最初的完成日期和移交后的准备状态。 舞台上的工作流程和隐藏的"舰队"情景保持了他们的规则. `IsPlannedBooking` 默认为 `true` 快速预约,包括省略字段的旧API客户端; `false` 允许以简单模式输入已完成的工作。 数据库计划没有更改 。  见 [执行以及自动和实时浏览器检查](simple-maintenance-workflow.zh-CN.md).

<a name="data-integrity"></a>

## 数据完整性

`MaintenanceDetail.Price` 仍为线总和,包括数量。  这保存了与计算、报告和文档的相容性。 `Quantity` 默认为 1; 更改目录不会重新计算先前保存的行或重命名它们 。 文档显示数量大于服务名称旁边的一个。

`MaintenancePayments` 存储操作,包括已取消的。 `Maintenance.PaidAmount` 仍然是现有报告的汇总;正常组织编辑不再覆盖报告。  新组织在任命产生后通过卡卡接受任命付款。

付款业务在有记录锁的交易中进行。 申请身份证可防止重新提交;预期支付的金额可防止过期卡。 重复取消不会减少金额两次. 服务更改并更新编辑器发送 PostgreSQL `xmin` 版本,所以它们不能覆盖较新的数据。

<a name="migration"></a>

## 移徙

`20260913163729_AddMaintenancePaymentsAndServiceBundles` 增加了付款记录、服务价格和服务组合组成。 先前存放在一个组织的正数 `PaidAmount`  作为期初余额迁移,标有“以前记录的”。 来源金额不变;实际收货日期不详,不显示为新付款日期. 个人车辆不包括在迁移中。

`Down`  删除付款日志和新的目录字段。  一旦投入使用,将失去付款细节和服务设定的构成,尽管 `PaidAmount` 总计还剩了。 完整的数据回滚需要迁移前的备份.

<a name="verification"></a>

## 核查

一体化检查包括反复付款、同时提出要求、呆牌、有原因取消、防止支付债务以上、进入另一组织、获得财务许可、保留旧价格和费用、有效的服务设置组成以及防范旧编辑。 界面通过三种情景检查,两种主题,宽度为320–1500 px.
