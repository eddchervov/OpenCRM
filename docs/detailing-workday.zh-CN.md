# 工作看板

[English](detailing-workday.md) | [Русский](detailing-workday.ru.md) | **简体中文**

> 本页为机器译稿。涉及部署、接口或数据变更时，请同时核对英文或俄文原文。

 这个屏幕是用于详细,汽车服务和车队组织的共享操作板. 统计图表仍保留在“统计”中,没有载入初始工作空间的背景。

<a name="contents"></a>

## 目录

- “计划”——选定日期的任命和以前日期的公开任命。
- “进行中”——所有工作都具有地位 `InProgress`,无论选定的日期。
- “准备”——完成等待设备移交的工作。
- “手提”——在选定日期实际移交的设备。

契约卡显示时间,车辆,服务,客户,电话号码,工位和员工. 用户在“Stages”和“Bays”之间切换;选择被保存在浏览器中。 宽屏显示对齐的列,中屏显示2个,而手机显示一个有切换器的被选中的列.

阶段标题使用柔和的颜色和图标:规划为灰色-蓝色,进行中为橙色,准备为黄色,移交为绿色. 已知的卡片使用本地的SVG标志. 使用链接的 make 选择标志 `Brand.LogoKey`,通过 API 作为 `vehicleBrandLogoKey`. 其造型并非从车辆型号名称中推断出.  如果没有设置密钥,客户端不知道它,或者被手动输入了制作,则没有出现标识. 进度栏仅显示实际完成的操作. 仅凭现成状态并不能将栏填满为100%,缺失的操作数据不会被假设的百分比所取代.

车辆名称或开通链接的常规点击会以一个模式在牌盘上显示预约.  它允许用户查看服务,收录相片,并进行计算,或者打开完整的配置来编辑预约和文件. 付款和状况的变化仍然全面存在。 逃出,关闭按钮,或者点击外出返回到棋盘上而无需更改日期,分组,或滚动位置;焦点返回到链接.  在电话中,对话框会填充屏幕。 链接尊重组织区段访问; Ctrl/Cmd-点击保持正常浏览器导航.

取消的预约,被删除的记录,被删除的车辆不出现在董事会上. 服务器返回每组前50张牌和全部计数. 界面最初显示五张牌,让用户扩展其余部分;完整的列表仍保留在预约科.

 一个没有工作的组织首先要采取紧凑的行动。 装入错误不会清除已装入的卡片, 包括重试动作 。

右上方的“所有预约”链接和开卡动作上的箭头被去掉;日期显示时没有内页头,箭头与标题一致。  在窄屏幕上,取景切换器和刷新控件共享一行.  只恢复了各阶段的有色标题;工位标题保持中性。

<a name="implementation"></a>

## 执行情况

- `packages/workspace/src/components/WorkspaceWorkdayBoard.vue` ——共享棋盘,日期,加载,权限,以及应答布局.
- `packages/workspace/src/components/WorkspaceWorkdayCard.vue` ——共享紧凑工作卡.
- `packages/workspace/src/api/workday.ts` - 合同和数据请求。
- `GET /api/v1/organizations/{organizationId}/workspace/workday?date=YYYY-MM-DD` ——共享被保护的API.
- `OrganizationWorkspaceQueryService.GetWorkdayAsync` ——在所有业务情景下共享工作日服务器查询.

API检查组织模式,成员,工作单元的可用性,以及查看工作的许可. 只有在有客户模块和相应的许可时,才返回客户姓名和电话。 创建反映权限和只读模式的按钮 。

计划日期作为日历日期发出,不作变更。  对于实际交接,浏览器发送 `timeZoneId`;服务器将所选的天数边界转换为 UTC 。

由服务处保存的工位字段“Bays”组合卡片,  它显示使用中的工位和“无工位”一栏;工位内的预约按计划时间排序。  一个单独的基于ID的连接工位目录仍然是未来的模型改进.

<a name="readiness-and-handover"></a>

## 准备就绪和移交

 在共享细节,汽车服务和车队卡中,完成工作与向客户移交设备是分开的.  所有三种情况都使用共同工作日板。

- “准备移交”完成工作并节省费用 `CompletedDate` 和 `ReadyForHandoverAt`.
- “交给客户”需要准备和确认,然后是记录 `HandedOverAt`. 尚未付款的,表格显示余额;交接时不自动标明已付款.
- “移交”需要理由,记录在历史上,并将记录退回等待移交。 完工日期、付款、里程和相片均保存完好。
- 要将交接记录交回工作,必须先取消交接. 恢复工作可以说明准备就绪情况和实际完成日期。
- 完成的旧记录仍然是“完成的”;未知的移交不是自动填写的。  如果设备仍在组织中,则可以明确标明准备状态.

保留已备妥和移交的记录 `MaintenanceStatus.Completed` 因此,财务报告和已完成工作日记继续象以前一样列入。 移交和取消不会重新计算里程或改变规划员任务的关闭日期。 服务器权限和交易中的行锁保护更改;重复的交接被拒绝.

详细的服务日记提供了“全部完成”、“准备交接”和“完成”。 其期间按工作完成日期过滤;交接日期取自工作日委员会。  在计数和标注前应用交接过滤.

移徙 `20260913150000_AddMaintenanceHandover` 增加了两个可作废的栏目和州与州一致的制约.  它跟随摄入量的迁移;已存在的行不变.  在运行新版本之前将其应用到目标数据库. `Down`  删除两栏并失去准备和移交标记;它不删除事件历史。

EF 模型匹配迁移; SQL `Up` 和 `Down` 被检查。

<a name="bay-visualization--prototype"></a>

## 工位可视化——原型

“视觉化”在详细介绍、汽车服务和机队工作屏幕旁边都有。  所有三种设想方案都使用共享组件。 `packages/workspace` 以及当前组织的工位和维护记录。

<a name="first-version-rules"></a>

### 第一版规则

- “进行中”的工作订单显示其车辆在指定的工位上,而不论计划日期。
- 计划的工作命令在日期和时间过后会变成红色。 过去的任用也是红色的;今天,没有时间的任用不被认为逾期了。
- 未来的任命出现在选定的工位名单中,但车辆没有事先在图表上显示。
- 暂停操作标记为“已停止”;这并不意味着命令的所有工作都停止。
- 一个工位上多次启动或已经到期的命令被显示为冲突.  小组列出每项任命,首先开始工作。
- 备妥命令有单独的清单;图中没有取消和移交车辆。 实际安置没有单独跟踪:模型有意依赖状态和时间表.
- 湾与当前相匹配 `Location` 字段,对大小写敏感,并与周围的白空间进行修剪。  有工作的未知和已停用的工位仍保留在示警图上。  没有工位的记录单独出现在一个列表中.

<a name="data-and-access"></a>

### 数据和访问

`GET /api/v1/organizations/{organizationId}/workspace/visualization?date=YYYY-MM-DD` 使用与工作日相同的成员、模块和工作视图检查。  它会返回三个非命题组的所有记录,没有50卡限制. 正常工作日API保留其限制. 菜单项需要允许查看工作和工位目录. 只有在工作卡的导航部分可用时才会出现与工作卡的链接.

数据每15秒在可见的标签中刷新一次;错误提供重试.  如果失败, 最后一个成功的观点仍然是警告 。 切换组织清除了先前的数据. 移徙 `20261017104518_AddBrandLogoKey` 添加可选选项 `Brands.LogoKey` 字段,最多64个字符,用于标识链接。  它在目录名称(包括已知的俄罗斯变体)上使用精确的匹配,为20个配有本地SVG的制作分配密钥,而无需更改制作或车辆关系. 正常的目录初始化将密钥指定给由内置数据所出而出的新已知的密钥,而不覆盖已存在的密钥. 手动创建的 make 有空密钥, 除非通过管理员 API 明确提供 。  要添加新标识,在客户端资产集中包含一个SVG并指定其密钥为制作记录. 单位 `AdminSaveBrandDto.LogoKey`,无效或编辑时被省略的字段保留了旧值;空字符串可以清除;最大长度为64. `AdminCatalogBrandDto` 返回已保存的密钥。 `Down`  只去除字段及其值; make table 和关系保留。

<a name="service-card--local-variant"></a>

## 服务卡——本地变种

用于详细,汽车服务和车队的共享卡保留了CRM的造型. 信头显示标志来自 `Brand.LogoKey`,任命阶段,以及已完成服务业务的实际数。 材料不包含在进行中;如果没有工作状态,卡片报告为零而不是零.  没有准备状态标记的旧的完成记录保留“完成”标签。

服务显示工人、操作状态、活动时间和线路数量。 计算结果、未清余额、客户和文件仍然可用在内容之外。  在狭长的屏幕上,“计算”向该块滚动并突出其重点。 材料、成本和工作调整都崩溃了;摄取量和完整的相册单独放在一个分页上,而一些照片出现在服务之外。 “通知”标签显示现有的客户通知。 改变服务、接收、支付和调整的许可仍然有效。

本地预览,运行 `npm run preview:visualization`  从 `src/OpenCRM.Frontend` 打开 `http://127.0.0.1:5178/tests/maintenance-card-preview.html#maintenance/1`. 密码 `?readonly` 参数启用只读模式。  它使用演示 API 响应和块突变请求;页面不包含在制作构建中.  此更改不需要迁移, 但服务器和客户端必须返回并读取车辆的新选项 `brandLogoKey` 字段。

 审查意见得到处理:初步报告在倒塌区块外可见,加载额外报告时出现错误,无法重新确定成功的进展。

 主可视化仍然是一幅三维工位图;没有单独的卡片视图,因为工作日会处理使用大小写的情况. 标记显示车辆和登记号,不重复。  摘要包括了被占用/自由湾和等待启动工作的组,暂停命令,没有工位的记录,以及准备移交的工作;被暂停的单个操作并不意味着整个命令被停止. 任务冲突单独显示. 选取的-bay面板从它的密钥,真正完成的工作计数,时间表和工人中显示出制作的标志. 常规的“查看工作顺序”点击打开现有模式;逃出返回选定的组,Ctrl/Cmd-点击保持链接导航。 查看权限由情景菜单决定. 错误发生后最后的数据自动刷新和保留不变。 3D 不可用时可提供简单的湾列表 。
