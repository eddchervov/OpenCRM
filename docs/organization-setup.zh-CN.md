# 组织设置

[English](organization-setup.md) | [Русский](organization-setup.ru.md) | **简体中文**

> 本页为机器译稿。涉及部署、接口或数据变更时，请同时核对英文或俄文原文。

设置向导在用户首次访问一个新的"详细"或"服务站"组织时,会在工作空间上自动打开. 标签匹配选中的情景 。  如果被解职,可以重新启用“继续设置”。 完成后,面板和按钮会从工作空间消失. 竣工后,服务区和服务可编为“董事”和“组织环境”的工作时间。 舰队组织不显示巫师。 组织设置包括一个单独的“工作时间和休息时间”部分。 设置存储和API共享;公共页面不变.

<a name="steps"></a>

## 步骤

1. **工作工位:** 已存在的条目预选。  您可以启用您需要的, 重新命名未使用的条目, 并添加您的条目 。
2. **服务:** 选择活动条目和价格。 空出的价格仍然未知,而不是成为零。 保存的维护记录及其价格不重新计算.
3. **工作天数和时数:** 设置每天的开关时间和休息时间。 时间表在日历中突出显示工作时间;顶端的测距字段和槽网格使用所选的日时. 时间安排外的预约仍然可以使用。 工作日不能过午夜。
4. **完成 :** 前往第一次预约或返回工作区。 所保存的数据可以在目录和组织设置中被更改.

“后”关闭向导。 已完成的步骤被存储在数据库;未完成的输入单独存储在每个组织的浏览器中. 过时版本的草稿不能覆盖服务器数据。 “ Skip” 无法从当前步骤中保存更改 。

<a name="data-integrity-and-access"></a>

## 数据完整性和存取

设置需要会员资格和成员资格 `workspace.profile.edit` 允许 。 订阅写入限制 `PlatformPolicy:Commercial:Enabled=true`.  该页面在未获得所需许可的情况下,以可适用的只读模式隐藏向导与员工. 需要服务器侧授权 。

 每一步都保存在一个单项交易中. 组织锁定和修订号可防止同时发生变动并挽救已过时的一步。  项目保留其ID和系统代码:普通目录初始化不会再创建已禁用条目. 外国身份证明,重复姓名,无效价格,无效时间表一律拒收.

使用中的服务,活动集的成员,或已有预约的工位不能被禁用. 正在使用的工位不能在向导中被重新命名,因为现有的任命是用名字与之相联的.

<a name="migration"></a>

## 移徙

`20260916100913_AddOrganizationSetup` 仅添加字段到 `Organizations`:向导步骤,修订,完成状态,工作日的起止,以及工作日. 现有组织得到的设置不完整,没有配置时间表。 移民不会改变预约、付款或目录。

`Down`  删除向导进度和调度;通过向导添加的服务和工位仍保留在现有目录中. 退后前考虑进度表设置的丢失 。

<a name="first-open"></a>

## 第一次打开

`SetupAutoOpenPending` 在一个组织创建时设置。 现有组织收到 `false` ; 更新不会迫使它们使用向导。  对于没有设置-管理许可的员工和只读模式的员工,自动显示被禁用.

 在目录加载后, 客户端在解析中记录第一个打开 `POST /setup/open`. 仅允许数个同时打开的窗口中的一个自动显示向导. 旗帜被存储在组织上,独立于浏览器. 关闭 X, Escape, 或“ later” 无法完成设置, 但自动显示不会再次发生 。  在设置完成之前,有权限的用户可以通过"继续设置"重新打开.

`20260916102622_AddOrganizationSetupAutoOpen` 添加一列布尔, 并带有 `false`  为已存在的行。 `Down`  只去掉第一个播放的旗子。

<a name="working-hours-by-day-and-breaks"></a>

## 每日工作时间和休息时间

 在服务站和舰队设置中,这一节被称为“工作时间和休息时间”;在“细节”中,它是现有向导的第三步。 共享编辑覆盖了所有七天. 每一天都可以被标记为一天放假或指定开闭时间,在不设人工限制的情况下会增加或去除休息. 服务器验证工作日、所需工作日时数、正持续时间、时限和相重叠的休息时间。  目前至少需要一个工作日。 超夜时刻表,节假日,以及特定日期的例外在本版本之外.  这些是组织工作时间,而不是雇员轮班。

每周的日程安排都存放在 `OrganizationWorkingDays`; 分页符被存储在 `OrganizationWorkingDayBreaks`. 工作日的复合键为组织/日;休息键还包括其起步时间. 整个一周的更新都在组织锁下进行 `SetupRevision` 在当前交易中。 设置 API 添加 `WeeklySchedule`; 遗产 `WorkingDays`/`WorkdayStart`/`WorkdayEnd` 字段目前仍为相容摘要字段。 遗留的写入格式如果可能损失不同的时数或中断所保存的日程,则会被拒绝.

 所有三个客户端的日历显示工作间隔,并取消间歇。 插槽网格显示选定的日时数和“外部工作时间”标记。  当选定工作日时,上行范围和网格使用相同的时数;可以手动更改范围以取景而无需更改组织所保存的日程. 服务站和舰队,同"细节"一样,显示全天日历范围为:00:00–24:00. 命令不只因为一天休息或休息而隐藏或禁止。

<a name="weekly-schedule-migration"></a>

### 每周时间表迁移

`20261009005033_AddOrganizationWeeklyWorkingHours` 增加两张带有外国钥匙和时间检查的表格,然后使用旧的共享时数迁移现有的每个工作日,没有间歇. 复制选定的工作日倒塌为一行 。  如果选中的天数包含无效的周数或缺失/ 逆行时数, 迁移会以错误而不是猜测时间表而停止 。  没有选定天数的组织仍然没有设定时间表。 旧列和命令不删除。

`Down` 只有在各组织没有间歇时间和日间时间不同的情况下,才删除新表格。  否则回滚就停止了,因为旧计划无法保存这些数据。  在这样的回滚前,导出完整的时间表,并单独决定是否将其转换为共享小时或恢复备份.  不进行自动数据关闭转换。
