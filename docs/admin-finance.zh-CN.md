# 订阅收款及自雇收据

[English](admin-finance.md) | [Русский](admin-finance.ru.md) | **简体中文**

> 本页为机器译稿。涉及部署、接口或数据变更时，请同时核对英文或俄文原文。

 本指南描述了可选的商业模块. 只有在 `PlatformPolicy:Commercial:Enabled=true`; 设置默认为 `false`. 部署在使用相应的工作流程之前,必须配置其付款提供者、通知服务、Hangfire和私人文件存储。


 在购买或续延工作空间计划之前,买方应说明是作为个人还是代表一个组织/独资商行事。  对于一个组织或独资企业,则需要法定名称或独资企业的全名以及10个或12个数字的TIN并有有效的验收和. 选中的细节在创建时保存在付款记录中。 仅凭工作空间名称并不能确定购买者的类型。 遗产付款保留 `unknown` 类型。

行政部分“财务”-“付款和认购”-“购买和自营收据”列出确认的采购,但不限制头300笔付款的结果。 取消的付款仍处于付款历史,但不算作购买,即使存有旧的、不正确的付款日期。 清单显示买方、TIN、用户、计划、金额、付款日期和付款状况。 记录可以被搜索和过滤;界面显示付款计数,总额,以及未标出已付款收据数. 30天的总额和支付清点采用确认的支付日期;金额为退款净额. 取消的尝试不是收入。

 在“我的税收”中开具收据并交给买方之后,一名管理人拥有 `Admin.Billing.Manage` 手动标记为发行. 需要添加或去除标记的理由;更改记录在 `admin.NpdReceiptAudits`.  该标记不向联邦税务局创建收据,也不向客户发送. 购买卡可以在一个FTS域名上存储一个HTTPS收件链接,一个注释,和一个PDF,PNG,或JPG文件最多可达5 MB.  文件被存储在现有的私有S3存储器中,并且只能通过认证的管理员路由下载. 调试从支付中去除文件引用;由于共享提供者通过散列重用文件,对象目前仍在存储中.

<a name="automated-monitoring"></a>

## 自动监测

购买表显示先用无标记收据支付的款项。 24小时以上的年龄被强调为内部监测目标,而不是法定期限。 管理员界面显示一个警告,其中包含此类付款的次数和有激活错误的已支付付款。 柜台在管理员界面打开后每分钟刷新;警告直接链接到购买和自营收据.  此通道不使用Telegram 。

“发送收件”按钮通过现有的通知队列将电子邮件排入用户的注册地址。  如果一个文件被附加,电子邮件包含一个保护的下载链接,有效期为30天;替换或去除文件会使旧链接失效.  如果没有附加文件,则发送已保存的FTS链接.  该表分别显示排队情况,电子邮件服务的接受情况,确认的交付情况,以及出错情况. 重复相同的请求不会创建第二个电子邮件;在出错后发送可以重新进行.  在成功发送后,新收发版本需要替换文件或链接. 将收据标出为签发的收据仍然是单独的管理人行动。

 每15分钟,一份背景工作就与约克萨核对了有限的一批付款.  对于一个丢失了网络hook的付款,它检查ID,金额,货币,和远程状态,然后运行与网页hook相同的订阅激活路径. 激活出错的已支付款项不会自动被重新启动,而是留在审查队列中。  若柳克萨确认注销而未付款,则对账清理错误的付款日期并删除购买清单中的记录;活动订阅访问权限必须单独检查. 调节表还记录部分和全额退款数额;表格显示付款毛额和退款后的数额。  这种自动化不发放退款或更正自营职业者收据。

密码 `AddBillingAutomation` 移出后,将退款数额、核对日期和指针加到最新的收件邮件上。 现有付款最初为零退款,在与YooKassa核对后予以更新。 倒转移会删除此数据历史. 已排定的工作和电子邮件发送需要运行的 Hangfire, PostgreSQL, 通知服务, 以及配置的文件存储 。

自营职业卖方的付款创汇申请不包括: `receipt`  根据联邦第54-FZ号法律用于收据的物件:自营职业收据在“我的税收”中单独签发。 YooKassa通过现有流量确认启动计划并记录成功付款日期。 示范和人工免费赠款不会产生付款或自营收入。

密码 `AddPaymentBuyerAndNpdReceipts` 迁移增加了买方的快照、付款日期、收据细节和审计记录。 旧记录 `completed` 状态,付款日期从改变状况日期或付款创建日期中重建;可能大致。 `Down`  删除此数据, 从而在实际销售完成后回滚, 丢失收货历史 。
