<a name="primary-priority"></a>

## 首要优先事项

员工工作空间是OpenCRM的主要产品优先。  它将管理员规划与细节、汽车服务和车队组织的实际工作联系起来。

 该解决方案被应用到现有的应用程序中,并使用共享服务器,认证,以及业务模式. 员工获得一个单独的紧凑接口,用于手机的优化,并且仅限于被选取的组织所授予的权限.  不为不同组织类型创建单独的客户端.

<a name="goals"></a>

## 目标

- 管理员可以在不依赖员工的口头更新的情况下看到工作何时开始,暂停,结束.
- 雇员可以看到他们的排队、积极工作,并且只能看到这项工作所需的数据和行动。
- 每项服务业务都跟踪实际执行情况。
- 雇员记录在对业务有意义的单位中消耗的材料。
- 所有重大行动都记录在历史上,不能无声地取而代之.
- 共享的工作流程在细节、汽车服务和车队组织之间是一致的;具体行业的能力属于具体的工作项目。

<a name="team-and-access"></a>

## 团队和接触

组织设置接口有一个部分, **“团队”。** 用户不需要理解雇员与组织成员之间的区别。

商业模式保留了这种区别:

- 雇员代表工人、工作任务和已完成工作的历史;
- 一个组织成员代表一个账户及其访问权限;
- 雇员可与组织成员联系;
- 取消准入并不删除雇员或其相关历史。

 从“团队”中,管理员可以:

- 创建一个没有 OpenCRM 访问的员工;
- 允许现有雇员进入;
- 邀请新人,同时创建他们的工作简介;
- 指定角色和权限;
- 取消访问而不删除历史;
- 解除一名员工的新任务

 一个账户在不同的组织中可能具有不同的作用。 选择一个组织会打开相应的工作空间.

<a name="work-execution-model"></a>

## 工作执行模式

个人行动状态与整体服务访问状态是分开的.

操作寿命周期:

1. 被指派.
2. 进行中。
3. 暂停。
4. 已完成。

服务访问生命周期:

1. 计划。
2. 进行中。
3. 等待管理员审查 。
4. 准备交接
5. 交出来.

开始第一次所需操作后,服务访问将移到进行中。 完成一次行动并不能完成整个访问。  一旦所有所需操作完成,访问将等待管理员的审查。 雇员不确认付款或交出车辆。

每一个开始,暂停,恢复,和完成都会产生一个单独的事件. 实际工作时间根据工作间隔计算。  对错误动作的更正被记录为有原因,作者,时间戳的单独调整,而不是默默地改变原始记录.

<a name="employee-workspace-1"></a>

## 雇员工作空间

 主要观点:

- 今天的工作;
- 积极工作;
- 分配的工作;
- 现有工作,如果该组织允许雇员自行提出;
- 工作在轮班期间完成。

工作卡显示:

- 车辆或其他设备及其登记号码;
- 工位或工作地点;
- 计划时间;
- 分配给雇员的业务;
- (一) 摄取详细情况、说明和“之前”照片;
- 核准额外工作;
- 所需和已经消耗的材料。

可用的动作取决于状态和权限 :

- 开始工作;
- 以必要理由暂停;
- 恢复;
- 添加注释和相片;
- 报告缺陷;
- 要求开展额外工作;
- 记录所消耗的材料;
- 完成雇员的操作。

雇员要求的额外工作不会自动提高价格。 报送管理员审批,经批准后方可加入服务访问.

<a name="materials-and-units-of-measure"></a>

## 材料和计量单位

雇员在为特定业务方便的单位记录实际物质消耗。 该系统将数量自动转换为库存基单元。

支助团体:

| 组 | 单位 | 约束 |
| --- | --- | --- |
| 已计数的项目 | 医生。 | 仅限全部数量 |
| 质量 | g, 公斤级 | 自动转换 |
| 音量 | ⁇ и | 自动转换 |
| 软件包 | 瓶子、罐子等 |  每个材料都配置了转换因子 |

实例:

- 获得3公斤洗涤剂后,其基值为3 000克;
- 消耗量300克,叶为2.7千克;
- 获得200升石油后,基数为20万毫升;
- 消耗量为3升和200毫升,残存量为196.8升。

数量作为 `decimal`.  每次库存变动都保留所输入的数量、输入单位、换算出的基准数量以及应用系数。  如果材料设置在较后时有所改变,这样可以理解历史。

已计数的项目只接受全部数量。 界面中的值省去微小后零。

雇员只能为从事积极工作而消耗材料。  它们不能收到库存、改变购买费用或删除变动。 消费通过扭转或调整历史记录的变动来纠正。

可以为某项服务配置标准的材料组成。 工作开始后,OpenCRM建议标准金额,员工确认或改变实际消费. 业务费用从实际消耗的数量和配置的存货估价方法计算。

<a name="permissions-and-audit"></a>

## 授权和审计

默认情况下,雇员无法获取财务、付款、计划、组织环境、成员管理、购买价格或其他雇员的工作。

服务器检查权限,组织成员,账户对员工链接,任务到操作,以及是否允许状态过渡. 客户端限制不是安全边界.

重大行动保留:

- 组织和服务访问;
- 操作;
- 雇员;
- 认证成员;
- 新旧州;
- 日期和时间;
- 理由或评论;
- 已更改记录的版本。

命令必须是一能的,并处理乐观的货币,因此反复点击或同时两次请求不能产生重复的过渡或存量扣减。

<a name="administrator-workspace"></a>

## 管理员工作空间

服务访问卡显示其业务的实际情况:

- 被指派者;
- - 开始工作和何时开始工作;
- 工作期间;
- 暂停状态和理由;
- 已完成和剩余业务;
- 额外工作要求;
- 材料短缺;
- 准备进行审查和移交。

更新会自动传送到工作区.  第一个版本可能使用共享的投票机制,后移动到SignalR.  这一工作流程不需要Kafka。

<a name="implementation-phases"></a>

## 执行阶段

<a name="1-business-model-and-access-foundation"></a>

### 1. 商业模式和准入基础

- 在“团队”界面中统一人员管理;
- 将雇员与组织成员联系起来;
- 界定雇员的角色和权限;
- 为个别行动添加执行状态和事件;
- 增加实际工作间隔和调整;
- 在服务器上执行权限和状态过渡;
- 添加迁移并对照项目规则加以验证。

<a name="2-employee-workspace-and-administrator-oversight"></a>

### 2. 雇员工作空间和管理人员监督

- 实施反应灵敏的员工工作空间;
- 执行启动、暂停、恢复和完成行动;
- 显示管理员工作空间的操作进度;
- 增加一个审查步骤,然后才能标明工作已做好移交准备;
- 添加自动刷新和清晰的通知。

<a name="3-materials"></a>

### 3. 材料

- 增加单位组和转换;
- 将库存流动移到正常数量;
- 支持接收和消耗相容单位的库存;
- 拒绝计数物品的分数;
- 增加服务标准材料;
- 支持雇员工作空间的实际消费;
- 在转换过程中保存成本、平衡和历史。

<a name="4-production-workflow"></a>

### 4. 生产工作流程

- 增加缺陷和额外工作请求;
- 增加雇员的照片和评论;
- 添加管理员批准;
- 增加实际时间、材料和费用的报告;
- 如果需要,请添加一个共享终端模式作为附加访问方法。

<a name="first-working-release-acceptance-criteria"></a>

## 第一项工作释放接受标准

- 雇员接受向正确组织发出的邀请和签名;
- 雇员只能进入工作空间和允许的业务;
- 管理者指派雇员从事个别业务;
- 雇员开始、暂停、恢复和完成;
- 管理员工作空间显示更新,而不更新手动页面;
- 完成一项业务并不结束其他业务或整个服务访问;
- 实际时间取自事件和间隔;
- 材料可以以公斤或公升为单位接收,并用克或毫升来消耗;
- a 计数物品不能分数消费;
- 正确计算库存余额、成本和变动历史;
- 重复请求不会造成另一种过渡或重复扣减;
- 所有变化都出现在员工和账户的历史上。
