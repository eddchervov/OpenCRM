# 员工工作区实现

[English](employee-workplace-implementation.md) | [Русский](employee-workplace-implementation.ru.md) | **简体中文**

> 本页为机器译稿。涉及部署、接口或数据变更时，请同时核对英文或俄文原文。

依据 : [雇员工作空间要求](employee-workplace.zh-CN.md),则 [ 总计划](plan.zh-CN.md),当前 [雇员规则](organization-employees.zh-CN.md).  该计划澄清了技术范围。 已完成的邀请函、接收表和数据迁移不再执行。 移动导航和CRM的完成部分已超出范围.  在此优先权之后,接下来的项目是端到端的汽车服务验证,并用Vite运单替换后建脚本.

<a name="scope-and-current-state"></a>

## 范围和现状

- 详细,汽车服务,和车队共享一个认证系统,业务模式,以及服务器. 雇员需要在客户关系管理系统内有一个紧凑的视图;没有为每个情景创建单独的客户端。
- `OrganizationEmployee` 储存任务和历史; `OrganizationMember` 代表账户及其权限。 雇员简介已经存在,但在这项工作之前,它与某一成员没有联系。
- 服务作为JSON存储在 `Maintenance.Details`,没有稳定的行ID。 两种服务编辑路径都重新创建了收藏. 操作事件不得指名列索引或名称.
- 服务状态目前 `Planned`, `InProgress`, `Completed`,以及 `Cancelled`;准备状态和移交情况作为额外日期储存。 完成某项服务目前标志着它准备立即移交;在引入管理员审查时,必须改变这一点。
- 清单已经接受克/克/毫升/升,但移动被存储在物品的单位中,而费用同步删除了以前的移动. 开销审计需要永久历史,并保存原单位.
- 密码 `employee` 角色目前拥有广泛的客户关系管理、库存和资金许可。 工人的作用必须是分开的,或者在打开工作空间之前,其有效许可必须受到管理员的明确限制.

<a name="phases"></a>

## 阶段

<a name="1-team-and-access"></a>

### 1. 团队和接触

1.  只有在同一组织内,才能将雇员与成员联系起来;一个成员可只与一个雇员的情况联系起来。 取消准入可以保护雇员和历史。
2.  让管理员在“团队”中管理链接并显示其访问状态。 设立无帐户的雇员仍然可以使用。
3. 添加浏览和执行员工自身操作的狭义权限。 默认情况下,工人无法获得资金,计划,购买价格,其他人的工作,或环境. 服务器检查会员,链接,以及任务独立于按钮能见度.
4.  当新人与雇员简介一起被邀请时,接受邀请必须在保持现有邀请流的同时将简介联系起来。

 第一个切片:将现有雇员与现有成员联系起来,并进行迁移、审计和服务器侧检查。  它不自动给予该成员新的许可。

 第一段状态:将现有记录联系起来,在服务中检查组织所有权,并使用复合外国密钥、账户独有性、版本检查和用于链接/脱链接的审计事件。  删除一个成员会以单独的事件删除链接。 向后滚回迁移会减少链接一栏,从而失去之后创建的链接;员工和成员简介仍然存在.

 第2至第3阶段的现状:服务行的稳定ID和旧的JSON记录的迁移,一个工人角色,服务器侧操作过渡与版本和请求密钥,时间间隔和事件,"我的工作"屏幕,管理员进度更新,以及有原因的返回工作被添加. 管理员通过现有的服务完成行动确认准备状态;在操作跟踪开始后,该行动需要完成每个服务行. 已启动的记录不能被取消,返回计划,或被删除,而正在运行的员工也不能与账户脱钩. 倒转工作跟踪迁移删除了日志和间隔,因此回滚后无法恢复执行数据.

 还实施了:在接受邀请时,配置创建和链接,在组织允许时自称未分配的工作,管理者在时间上改正并给出理由、实质问题和每次操作的回报,笔记和相片,批准额外工作,以及一份生产报告。 “我的工作”与行政科分开,只显示现任雇员的任务、他们的计划。 时间、阶段、工作价格和执行行动。 雇员用户看不到成本价格或购买价格。

货包在收货时有固定的基单位数量记录. 雇员可以全部或部分消费,运动保留输入的数量和换算系数。 自动建议某一服务的标准物资数量尚未执行:目录储存服务链接仅供服务包使用,没有材料对服务链接或标准数量。 服务器集成测试使用此寄存器中包含的通知项目;需要容器的检查需要多克. 迁移将不同相容单位中现有的同名存货项目分开保存历史;新项目使用g,ml,或pc.

向后滚回基单位迁移可以恢复先前的千克/升转换后余额.  如果迁移后在更大的单位中创建了同名新项,则回滚可能需要解决独有性冲突。 `(OrganizationId, Name, Unit)`  先说.

向后滚回软件包因子迁移删除存储 `PackageQuantity` 数值;完成的移动保留其记录的原始数量、单位和因数。

<a name="2-operations-and-time"></a>

### 2. 业务和时间

1. 给每个非物质服务排一个稳定的身份证. 移去旧行而不失名取名,出价取出,出量取出,或出外派出. 两种工作组合的编辑路径必须保留一个不变操作的ID,并阻止删除一个有执行历史的操作.
2. 与服务状态分开存储运行状态:指定 + 进行中 → 暂停 → 进行中 → 完成. 开始并恢复开放工作间隔; 关闭和完成工作间隔。
3.  每个命令接受一个操作版本并请求密钥,在原子上验证过渡,并存储一个单独的事件:组织,服务访问,操作,雇员,成员,新旧状态,时间,理由,以及版本. 重复同样的请求返回上一个结果 。 同步更改返回冲突而不创建第二个事件 。
4. 暂停需要一个理由。 时间或错误的过渡修正是单独的事件,有原因和作者;源事件不更改.
5. 开始第一次所需操作后,服务访问将移到进行中。 完成一个操作不能完成服务.  一旦完成所有所需的操作,它就等待管理员的审查.  只有审查标志可以移交;雇员不处理付款或交出车辆。

<a name="3-workspace-and-oversight"></a>

### 3. 工作空间和监督

- 在电话中,雇员看到今天的工作、积极的工作、分配的工作和在轮班期间完成的工作。 只有在组织设置中启用时,才会显示可供自认的工作。
- 工作卡包含设备和登记号码、工位、计划时间、雇员的业务、接收细节、核准的增补和材料。 动作取决于权限和状态 。
- 对于每次操作,管理员都会看到员工,时间,暂停和理由,剩余的工作,以及审查排行.  第一个更新机制是共享投票请求;更改出现时没有重新加载页面,用户可以看到一个已停用或已失效的刷新.
- 在复核期间,管理员可以确认准备状态或返回操作,以说明理由和单独事件进行工作.
- 用户为 `maintenance.edit` 可以通过“工作控制”对话框为雇员指定、积极或暂停的工作进行标记。 需要说明理由;事件记录了提交人和原雇员。 开放间隔是关闭的,没有为从未开始的工作增加时间.  该动作在服务进行期间和完成后一直持续到移交;服务器保护被取消和移交的记录. 重复命令不会产生第二次事件; stale 版本返回冲突 。

<a name="4-materials"></a>

### 4. 材料

- 基本数量作为 `decimal`: g, ml, 或整个 pc. 收据可能使用克/升;消费可能使用克/毫升和相容较大的单位。 包件使用材料的固定换算系数。 计出的数量总是整数.
- 移动存储输入的金额,单位,因数,基数,成本,组织,服务访问,操作,雇员,成员,并请求键. 更正不删除上个移动;它会产生倒转或调整。
- 雇员只能为自己的现行业务消费库存;他们无法领取库存、价格和删除。 余额不能为负。  建议服务的标准数量,但费用是按实际使用和存货估价方法计算的。

<a name="5-production-workflow"></a>

### 5. 生产工作流程

- 缺陷、评论和相片属于特定操作,管理员可以看到。
- 追加工程申请在批准前不改变订单组成或价格. 管理员的决定被存储为事件;经批准的工程会得到自己的操作.
- 时间、消耗、成本和调整的报告阅读了节省下来的事件和变动。

<a name="acceptance-scenarios"></a>

## 接受设想

| 假设 | 工作卡背景和监督 |
| --- | --- |
| 细节 |  项目、准备和申请阶段、治愈时间、照片之前/之后、移交前涂层质量审查。 |
| 自动服务 | 工作订单,诊断,缺陷,批准新增工程,部件,移交前进行技术检查. |
| 舰队 | 拥有设备、里程/引擎小时、定期维护、检查、缺陷审查和文件;不需要外部客户。 |

共同标准:账户只接收其在各组织的作用;服务器拒绝另一个员工和另一个组织的任务;重复命令不会产生第二次过渡或扣减;同时版本冲突;时间等同关闭间隔的总和;历史不能追溯编辑;完成一个操作不会关闭服务;在管理员之前无法进行移交  审查; 更新进度而不需手动刷新 。 材料检查包括3公斤-3 000克、200升-20万毫升、较小单位的消耗、成本、平衡、整块和校正历史。

在每个阶段,将迁移与其邻居和EF模型进行比较,构建,运行服务器权限/货币/历史测试,构建所有三个客户端,并在两个主题的电话和桌面上检查接口.
