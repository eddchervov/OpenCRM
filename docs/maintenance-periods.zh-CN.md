# 保养周期

[English](maintenance-periods.md) | [Русский](maintenance-periods.ru.md) | **简体中文**

> 本页为机器译稿。涉及部署、接口或数据变更时，请同时核对英文或俄文原文。

一项预约包括计划期间、服务、车辆、客户、照片和计算。  每天不需要单独的维修记录。

<a name="dates-and-times"></a>

## 日期和时间

- `PlannedDate` + `PlannedStartTime` - 计划开始。
- `PlannedEndDate` + `PlannedEndTime` ——计划结束.
- `CompletedDate` ——实际完成日期;改变状态不以它来取代计划期间.
- 日期按项目使用的格式作为日历日期存储. 独立的时区不转换为另一个时区.

默认起止时间为同日.  例如,您可以在一天的10:00开始,两天后的18:00结束.  这两次预约都需要多日预约。 结束时间必须严格地晚于开始时间;一个无效的时段不再沉默地更改为一小时.

 无时间的单日预约保留了以前的行为:出现在未定时的预约中,没有预留工位.  如果只提供单日预约的开始时间,则服务器在1小时后会节省一个结束时间,包括整个午夜.

<a name="bay-occupancy"></a>

## 湾入住

选中的工位被占用 **整个期间的连续**.  本保留包括干燥和储存日。 在一个预约范围内,不同工位上的不同工作间隔不在这一阶段。

重叠定义为 `startA < endB && startB < endA`.  如果一个预约在11: 00结束,另一个可以在11: 00开始. 00:00结束不占用下个日历日.

 在设立、编辑、重新安排或恢复一项预约时,将检查是否具备。 保存的 API 使用了已有的 `IApplicationUnitOfWork`.  在交易中,一个PostgreSQL锁按组织顺序检查和保存可用性并实现工位名称的规范化.  这也防止在重叠期的不同日子里同时提出请求。

取消和被删除的预约不会阻碍时间。 已完成的预约保留了计划占用期:实际完成不改写原计划。  在编辑时,预约本身被排除在冲突之外.

表格检查整个范围,通过 `occupied-slots?date=...&dateTo=...`. 答复包括提示和分钟的绝对起止时间,从选择时间的第一天起抵消。  即使接口先前显示湾是可用的,服务器侧面验证仍然具有强制性.

<a name="interface-and-related-data"></a>

## 接口和相关数据

- 快速详细及服务站创建,全版编辑,重排,和遗赠个人表格发送结束日期.
- 改期保留了这一时期的天数. 结束日期可以另行调整.
- 该日历选择与可见范围重叠的预约,包括较早开始的预约.
- 槽只剪切到选定日期的边界 。 整个期间仍在数据库中。
- 预约、客户和车辆卡,加上时间表清单,显示多天的期间。
- 工作日观点将连续预约与以往的预约区分开来;对于在选定日期结束的连续工作,则显示相应的标签。
- PDF和Word文件列出了计划期间与完成日期分开.
- 服务、付款和材料仍为一次预约。 计算和财务会计规则不变。

现有的共享维护机制得到延长;没有增加单独的多日预约实体或新的服务。 公共网页没有更改。

## 移徙

加上无效的 `Maintenance.PlannedEndDate` 并把它从现有的 `PlannedDate`. 期限不是为旧预约而发明的。 迁移元数据、设计师和快照符合实体框架核心10.0.7。

 在运行新代码之前, 应用迁移到数据库 。 旧代码与所添加的可失效列相兼容. `Down`  删除该栏,从而失去新的多日预约的结束日期;滚动申请时保留该栏。

<a name="verification"></a>

## 核查

整合测试通过Testcontainers使用临时的PostgreSQL 15和RabbitMQ,而不是生产数据库或队列. 其中包括:

- 单天和多天间隔,包括月和年的界限;
- 中间日入住,午夜入住专属终点;
- 相邻间隔和冲突;
- 重新安排时间、编辑而不丧失结束日期、减少相互冲突的变动;
- 两个同时预订一个工位;
- 移徙应用和模型/图示的一致性;
- 工作日视图中实际完成时间和计划期间的独立性。

TypeScript/Vue 构建,时间选择功能,以及所有三个日历中的多日事件转换也都经过了检查.
