# Правила проекта OpenCRM

## Разработка

- Перед изменениями изучай `.editorconfig`, правила в ближайшем `AGENTS.md` и стиль соседнего кода.
- Делай минимальные изменения по задаче. Не меняй несвязанные файлы, поведение и публичные контракты без необходимости.
- Для C# используй стиль проекта и соглашения Microsoft. Предпочитай ранний выход, понятные имена и простые методы.
- Новые комментарии и документацию в исходниках пиши на русском языке. Комментируй причины и ограничения, а не очевидные действия кода.
- Сохраняй кодировку, переводы строк и формат существующих файлов.
- Не добавляй секреты, персональные данные, действующие адреса и ключи в исходники, тестовые фикстуры, примеры настроек или логи. Локальные значения храни вне репозитория; для примеров используй явно фиктивные значения.
- Перед завершением проверь затронутую сборку и уместные сценарии тестирования. Сообщи о непроверенных сценариях и ограничениях.
- Не выполняй `git commit`, `git push`, создание тегов или публикацию без явного разрешения пользователя.

## Ссылка GitHub

Ссылка GitHub проекта в интерфейсе всегда ведёт на `https://github.com/eddchervov/OpenCRM`; общий адрес задан в `Helpers.ProjectBrand.GitHubUrl`. Ссылки на источники и лицензии сторонних библиотек сохраняются.

## Авторство

- Сохраняй видимую подпись «На базе OpenCRM» со ссылкой `https://github.com/eddchervov/OpenCRM` на сайте и в рабочем интерфейсе. Название конкретной установки не заменяет эту подпись. Имя и ссылка автора в интерфейсе не обязательны; сведения об авторе сохраняются в README и LICENSE ядра.
- Условия использования определены в корневом `LICENSE`; дополнительное условие об авторстве входит в лицензию OpenCRM Attribution License 1.0.

## Базовая поставка

- OpenCRM должна запускаться как самостоятельная CRM после настройки своей БД и локальных секретов, без обязательных сервисов или настроек прежнего владельца.
- Парольный вход, регистрация и базовая работа CRM не зависят от SMTP, аналитики, платёжного или ИИ-провайдера. Действия внешних интеграций показывай только при доступной конфигурации.
- Публичная навигация нейтральна. Защищённые страницы направляют гостя на вход; API сохраняет 401/403 и проверки прав. Навигацию проверяй до и после входа, включая устаревшую сессию.
